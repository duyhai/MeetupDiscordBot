# 1.5 Gen Wrapped Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A linked member runs `/wrapped` and privately gets their year with the group as an embed, with an opt-in Share button that posts it to the channel; one Meetup build per member per hour, cached in Redis for the season.

**Architecture:** A pure stats module (`computeWrapped`) over fixture-shaped event lists, a companion resolver that names only linked members present on the server, a thin Redis cache + in-process limiter, a build orchestrator that reads Meetup with the member's own token (organizer credential as the RSVP-history fallback only), an embed formatter, and interaction handlers wired into one `@Discord()` class (slash command + share button) registered in `src/commands/index.ts`.

**Tech Stack:** TypeScript ESM (imports end in `.js`), discord.js v14 / discordx, dayjs with tz, vitest (network blocked), Redis via `KeyValueCache`.

**Spec:** `docs/superpowers/specs/2026-11-10-wrapped-design.md`.

## Global Constraints

- Linked members only; unlinked members get the nudge (spec copy) and no Meetup call, no alert.
- Co-attendees are shown only as Discord mentions of members who are linked **and present on the server**; never a Meetup name or id of someone else, in replies or in the cache.
- Default reply ephemeral; shared post `allowedMentions: { parse: [] }`.
- Limiter: `FixedWindowLimiter(1, 60 * 60 * 1000)` keyed by Discord user id, hit taken only for a build and only after the Meetup token is in hand.
- Cache key `wrapped:v1:<discordUserId>:<year>`; TTL until 1 Feb of year+1 (`America/Los_Angeles`), minimum 86 400 s.
- Share guard `wrapped:shared:<discordUserId>:<year>:<channelId>`, `exclusive_set`, TTL 86 400 s.
- Year boundaries and "as of 31 Dec" cutoff in `America/Los_Angeles` via `tz()`.
- Hosted events union into attended by id. Cancelled titles (`hasCancelledTitle`) dropped from both.
- Attendee filter `['ATTENDED', 'YES']`; fan-out via `mapWithConcurrency(…, 5, …)`; only the Wrapped year's events are scanned.
- Named companions: 3; lookup cap: 25; ties: count desc, then Meetup id ascending (numeric-aware).
- Slow threshold 10 000 ms → "Still building…" + DM delivery, falling back to ephemeral follow-up.
- `/wrapped` options: `year` integer 2015..current (default current year, LA), `refresh` boolean.
- Every new `@Discord()` class is listed in `src/commands/index.ts` (the registry test enforces it).
- `no-await-in-loop` is an error: use `mapWithConcurrency` / `getPaginatedData`, or `// eslint-disable-next-line` as the client does.
- Integration tests: throwaway `postgres:16` on :55432 and `redis:7` on :56379.

## Review Focus

1. A member whose stored Meetup token belongs to a different account than the one linked → "account-mismatch" reply, nothing built, no limiter hit lost. (Task 4 + Task 6)
2. An event in the RSVP list dated in the next year's first hours UTC but still 31 Dec in LA → counted in the Wrapped year. (Task 1)
3. Attendee fetch throws for one event → whole build fails cleanly through the wrapper; nothing cached. (Task 4)
4. Share clicked from a DM after the member left the server → refused, guard released. (Task 6)
5. `year` below 2015 or above the current year → validation error from the command, no Meetup call. (Task 7)
